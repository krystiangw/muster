# Four audits of the running service, 2026-08-17

Not a review of a diff. Four agents were given full access and pointed at the
deployed instance: one for security, one for whether the thing is worth using,
one for the human's experience, one for visual craft. They created their own
projects, wrote their own boards, and cleaned up after themselves. What follows
is what they found, what shipped, and what was deliberately not done, because
the second list ages worse than the first if nobody writes down why.

The fixes are in `7e23008` through `4a089fc`. The security audit's own notes
live in `security-audit-2026-08-17.md`.

## Shipped

**Escalations mail the operator.** The largest finding, and it came from the
value audit rather than the security one: the whole product promises "ask the
human", and nothing left the building. An agent that stopped at three in the
morning stayed stopped until somebody happened to open a page. One message per
project per hour, only to the address that claimed the project, and a failed
send gives the hour back rather than buying silence with a message nobody
received.

**The OAuth token endpoint stopped minting permanent admin keys.** Every refresh
a normal client makes used to create a project-lifetime credential with no rate
limit; the audit measured sixty two live keys on one project. An hour now, with
`expires_in`, and claiming a project no longer clears that expiry along with the
project's own.

**Anonymous feedback stopped being able to blank an existing report.** A second
report of the same title rewrote the body and reset the labels, so any passer-by
could delete somebody's triage by sending the title back with different words.
It is a timeline note now, and the create-or-note decision is taken by the write
rather than by a read before it.

**Every timestamp is relative.** They were bare UTC with no label, which at two
minutes to midnight in Warsaw meant a card written ten minutes ago read 21:48
and a live claim read an hour in the past. The exact instant is in the tooltip
and in `datetime`.

**Closing an item releases its claim.** A finished card sat in "In progress"
until the lease ran out, contradicting this project's own rule that an item is
in progress exactly when it has a live claim.

**A person can ask for a project from the read link.** See the decision below.

Plus: `/inbox` distinguishes "not answered yet" from "never filed"; questions
are ordered by priority on the read page, the way `/operator` always ordered
them; assign and tag confirm what they did and a move says it took the card on a
lease; a handle's colour takes its lightness from the theme rather than from the
hash; the dark scrim stopped being mixed from the text colour; priority is on
the card; the layout editor is folded away; tables become cards on a phone.

## The one decision that went the other way

Both the value and the UX audit recommended dropping the project token from the
claim form on the read page: the person holding the link is exactly the person
without the token, and the funnel showed nobody had ever completed a claim.

A decision audit read the code and answered no, on a ground neither had: **owning
a project is a door that opens one way.** Nothing in this service ever sets
`claimedBy` back to null, an owner mints admin keys at will from `/operator`,
and an owner can narrow the project so the old link answers 404. A read link
that could take a board would turn a forwarded URL into a permanent loss with no
repair, where today a leaked link is an incident that rotating the link fixes.

What shipped instead gives the link the half it was missing: somebody signed in
can *ask* for the board, the ask lands in the agent's inbox, and the agent
answers with `POST /share`, which is still the only thing that moves ownership.
The number that was missing is now recorded beside the funnel rather than in it:
"nobody claimed one" had two very different explanations and no way to tell them
apart. Beside, because asking is not a stage every claim passes through, and a
stage that can exceed the one above it is a stage nobody believes twice.

## Deliberately not done

**Consolidating the discovery documents.** The value audit counted 74 reads
across `llms.txt`, `agent-signup.md`, `agent-access.json`, `mcp.json`,
`ai-plugin.json` and `openapi.json`, with zero registrations attributable to any
of them, against 57 reads of `skill.md` which is the only one anybody signs up
after. The recommendation was to keep two and redirect the rest. They cost a
string each, they are what the Let Agents In checks look for, and a discovery
surface that nobody used in the first week is not evidence that nobody will.
Revisit if they are still at zero when there are real users.

**Removing OAuth dynamic client registration.** Also recommended on the grounds
that nobody came through that door. It is now the only place issuing a token
with a lifetime, and the code is small and tested. Keeping.

**An insights page in the UI.** Telemetry has exactly one reader, and
`tools/insights.mjs` answers everything already. The UX audit's own measurement
argues against it: the most polished part of the interface is the part nobody
has touched, and building a second one of those costs the same and earns the
same.

**Drag and drop, again.** Still zero cards moved by hand, on a board that has
been live for a day. The move control stays a select and a button.

**Correction, 2026-08-18.** That last paragraph was written at 01:37, sixteen
hours into a window in which no hand move could have been recorded at all: the
security fixes above added `Referrer-Policy: no-referrer`, browsers blank the
`Origin` header under it, and the same-site check on the capability pages
refused every form posted from our own board between 09:37Z on the 17th and
06:55Z on the 18th. The decision stands for now, because the count was zero
before that window opened too, but the sentence above is not the evidence it
reads as. The count is worth re-reading a week after a board has been in
somebody's hands, and `tools/insights.mjs` names the blind window beside it.

## The pass over the fixes themselves

A fifth agent was pointed at the four commits rather than at the product, and
asked one question: did these repairs land everywhere the fault was. Seven
times the answer was no, and the shape repeats often enough to be worth naming.

**A fix lands on one path and not on its twin.** Closing an item releases its
claim, but hygiene closes items too, and that path kept the claim. The HTTP
inbox learned to separate "not answered yet" from "never filed", and the MCP
inbox, a second implementation of the same thing, had already drifted: it paged
fifty escalations and split them in memory, so an open question fell off the
end once a project had fifty answered ones, and it never applied the "already
acted on" filter at all. Claiming a project clears the expiry off every child,
and the commit that curated that list dropped the OAuth client registration.

The lesson is not "check the twin". It is that a second implementation of one
behaviour is a fault waiting for a schedule, so both inboxes now call one
function, and the browser claim form calls the same code the API route does
instead of making an HTTP request to our own public URL.

**A fix in one direction opens the other.** The move confirmation was escaping
too little and printed markup; assign and tag were escaping too much, and an
owner called O'Brien came out as `O&#39;Brien`. Both because a notice is words,
and exactly one layer is allowed to turn words into HTML.

**A test that passes without reaching the thing it names.** The test that was
supposed to prove a read link cannot take a project never reached a single
check: the route called our own base URL over HTTP, the suite's base URL does
not resolve, and the 500 was swallowed. It now walks four wrong credentials and
one right one.

Then the review of those repairs found two more of the same kind in them, and
the review of *that* found three. Each round was smaller than the last, which
is the only reassuring thing about the sequence.

## What the audits agreed was working

Worth recording, because a list of findings reads as a list of faults and these
are the parts not to trim in a later pass: the `:target` card preview with no
JavaScript; the notice after a move being built from the board's own columns
rather than from the URL; "N item(s) match no column", where the board admits
what it did not show; the identity chips; the column hints that explain
themselves; and the sign-in screen, which the UX audit called the pattern the
claim flow should have been copying all along.
